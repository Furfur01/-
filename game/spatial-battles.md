# 真实战场与独立靶场

## 使用

重新启动 Node 服务后，从主界面的「战场」或交战任务的「进入战场」进入。默认显示舰队全景，拖动旋转、滚轮缩放，Shift 拖动平移。点击远处编队标记，或用顶部编队、舰船选择框，选择一艘真实舰船。

「亲自驾驶」接管自己的存活战斗舰：右键转向、W/S 调油门、Space 主武器、R 导弹、T 换目标、X 对准目标、V 切换座舱/舰桥与追踪、G 交还 AI。仅显示该舰配备的武器；炮塔和近防保持自动工作。退出页面、断线或被击毁均不会暂停战斗。跨战场接管会自动释放前一艘舰船。

舰船档案的「进入靶场」仍进入独立练习。战场列表也提供靶场链接。靶场不读取战斗记录，不提交真实驾驶指令；给靶场 URL 添加 battle/replay 参数也不会将它变成战场。

历史战报可以暂停、倍速、拖动进度及跟随舰船，不能接管。旧战报保留原结果，不重新计算。

## 战场画面

小规模交战优先保留靶场表现：总入场单位不超过 128 艘时，近中景优先使用原始完整材质、舰体、炮塔和推进器；远景切换原舰体生成的低模，每艘存活舰船始终独立显示，编队标签只用于选择。观战与驾驶直接调用靶场共用的 `drawCombatEffects` / `drawExhaust`，保留体积光束、实体弹丸、导弹尾迹及粒子；贴舰护盾命中使用真实剩余电量。当前试玩目标为双方各 50 艘，可用 `node scripts/launch-battle-trial.mjs --small` 启动隔离存档。更大舰队仍全量模拟，并沿用分级显示；所有规模统一调用靶场武器表现。高级测试舰型也生成低模，远景舰体保留最小可见尺寸。导弹按测量发射口逐枚出舱、点火转弯，每枚拥有独立碰撞与分摊伤害，待发齐射随存档保存。


默认「交火视角」从己方主力舰后侧观察并缓慢追随其交战方向，拖动镜头后转为自由观察；「舰队全景」按存活舰队范围取景。选择编队可靠近查看，驾驶和跟随仍对应同一艘真实舰船。

原始精细舰体按屏幕占比、三角形预算和实际帧时实例化显示，敌我使用同一细节规则；近处补齐原始炮塔。最远的小型舰保留编队代表与真实数量。尾焰来自原始喷口；光束亮芯、弹丸尾迹、护盾命中环与爆炸来自服务端事件或飞行弹丸，表现层不生成伤害。尾焰和短时命中特效单独限制绘制预算，避免密集交战拖慢驾驶。

源文件为 `scripts/hangar-source/battle-presentation.js` 与 `live-battle-adapter.js`。靶场不安装这些战场模块，保持原有显示与练习模拟。

## 实现边界

- 星际航行的舰队模型是不可操作的任务表示。战斗中每艘舰船独立模拟；远景每个编队显示少量真实成员及存活数量，中近景展开。显示选择不参与命中或结算。
- `spatial-profiles.mjs` 是本项目的空间玩法参数表：射程、转向、冷却等不是 APK 恢复数据。每批入场固定科技与参数，只开放正式目录中的九种战斗舰驾驶。
- `spatial-battle.mjs` 以 50ms 步长模拟；空间索引与错峰索敌限制单舰查询量。双方全灭或一方全灭结束，十分钟仍双方存活则平局。增援不延长时限，交战舰不能撤退。
- `engine.mjs` 管理任务占用、同方增援、第三方排队和唯一结算。建成、部署、返航及跳跃抵达的防守单位加入已有战斗；战略导弹仍可摧毁被战斗占用的防御，并保持不可修复规则。
- `battlefield.html` 独立加载战场控制器。`flight-runtime.js`、`ship-renderer.js` 与模型数据由靶场和战场共用；`hangar.js` 保留为同一构建内容的兼容输出。修改 `scripts/hangar-source/` 和构建脚本，再运行 `npm run build:command`，不要直接编辑生成文件。
- 完整检查点保存在存档旁的 `.battles/` 目录，世界存档使用引用；两者需要一起备份。先写不可变检查点，再原子替换世界存档。旧存档迁移只补充空战斗集合。关闭浏览器仍继续模拟，服务重启按事件时间顺序补算。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/state` | 当前玩家可见的战斗摘要及任务关联；不包含完整轨迹 |
| `GET /api/battles/:id` | 权威快照、逐舰状态及静态元数据 |
| `GET /api/battles/:id/events` | SSE；200ms 推送状态与新增事件，增援时刷新元数据，结束发送 finished |
| `POST /api/battles/:id/control` | 同源 claim / input / release；输入只含操控意图 |
| `GET /api/replay/:id` | 新战报返回 version 4 空间记录；旧战报使用原数据 |

驾驶校验所有权、存活状态、正式舰型、输入范围和递增序号。一名玩家跨战场只能控制一艘舰船，两秒无有效输入后恢复 AI。舰船的护盾、舰体、位置和冷却不随控制切换重置。

## 验证

`npm test` 运行经营、派遣、模型、战斗、回放与存档测试，包括 20,000 艘真实任务结算。新增测试还覆盖远景展开数量守恒、离线事件顺序、增援科技冻结、十分钟平局、辅助导弹、返航增援及战略导弹不可修复。

`node tests/battlefield-flow-selfcheck.mjs` 使用独立存档、临时端口验证九种正式舰型接管、只读回放和最终损失一致。`node tests/spatial-ui-selfcheck.mjs` 在 1920×1080 Chrome 下记录 1,000 / 3,000 艘混编战斗的观战、驾驶帧率、V8 内存和模拟耗时，并检查靶场仍独立运行。浏览器脚本使用当前电脑已有的 Playwright 运行时。

证据分别位于 `output/playwright/battlefield-flow/` 和 `output/playwright/native-battle/`。性能使用每种视角 30 秒采样，记录平均帧率、最慢一秒帧率、p95 帧时及显卡信息。驾驶采样使用守护者，双方护盾与舰体科技为 10，以免采样中舰船被击毁导致视角变为观战。结果仅代表当前电脑的无头 Chrome 测试，不是其他显卡或任意舰队规模的性能保证。
