# 近地轨道交战

正式星球战斗创建时保存 `environment` 和当地星球 ID。曲速退出、星图现场和回放共用当地模型与近地坐标；真实战场的独立链接会进入同一个星图现场。已有战斗及旧回放未携带环境时补齐近地显示环境，保留原坐标、事件和战损，不重新模拟。

- 防守舰队在大气层附近集结，自动迎敌时守住星球上方；进攻舰队从外侧靠近。
- 火箭、激光、磁轨、中子、等离子及护盾设施作为独立实体部署在浮空堡垒上。模型暂用底座、发射架、炮管和穹顶区分，使用原有攻击、护盾、耐久及战后修复规则。战略导弹仍走原有导弹任务。
- 星图中的舰船比例为星球显示半径 × 1.3 / 12000，出舰、抵达和交战共用。新战场远景不会再把船体强制放大到六个像素。特写靠相机靠近完成。
- 防御实体仅在实时交战及战斗回放中显示，结束或离开战斗后隐藏。战斗期间保留当地星球的地貌、殖民地和 NPC 外观，不绘制替代星球。
- 堡垒沿当地星球半径 1.3 倍的同心球面排列，保留离地间隙，不跟随地表自转。没有额外承载大底座，也不削平地形或改变 NPC 原模型。舰船、炮塔、弹道、曲速落点和回放使用同一轨道变换。恒星不再随战斗聚焦或缩放淡出。
- 舰船不能进入地表以下，武器不能穿过星球内部。空目标仍正常结算搜刮返航；情报计数包含已进入战斗的防御设施。

历史近地战斗记录保存在 `output/playwright/planet-battle/`。

历史当地模型记录保存在 `output/playwright/local-fortress-site/`；对应独立测试已清理。

阵地使用可扩建的浮空六边形堡垒群（`game/fortress-layout.mjs`）。大六边形缩小为原模型的 72%，中心和六个顶点都是通用槽位：每个位可放一座大型炮塔或一个小六边形。小六边形的中心与六角可放火箭、轻型/重型激光、中子炮，模型相应缩小；磁轨、等离子和护盾设施使用大型槽位。优先填充已有小六边形，再使用空槽，满后沿六边形环扩建。布局 v2 保存在战斗环境中，增援不移动已有位置；v1 旧回放保留原尺寸与槽位。

堡垒使用共享的精细几何和实例化绘制：分层斜墙、装甲门、肋柱、顶点平台、中央堡座、通风设备、灯带及邻接通道。炮台使用用户提供的 Imperial Defense Foundry 模型（独立底座、水平回转及俯仰节点）。阵营识别装甲与灯具为友蓝敌红，武器能量颜色独立；炮口与真实弹道使用同一份生成坐标。堡垒建筑是场景结构，不增加独立血量。完整堡垒和炮台仅在迎战与历史回放中显示，战后隐藏。星图和独立战场共用模型。

模型重导入：`node scripts/import-defense-foundry.mjs <HTML路径>`，再调用 `buildNativeBattleAssets` 并构建 Three.js 资源。文件中的七种炮台全部保留；当前游戏已有六种对应单位，质子炮工厂与炮口资料保留，未凭模型新增其经济或战斗配置。两种护盾设施继续使用原模型。

轰炸机攻击地面设施时飞向目标上空约 140 米并重复掠过，不再停在固定 850 米远程阵线。驾驶会话按页面隔离；快照不能让旁观页面自动接管，旧页面的输入或释放不能影响新驾驶页面。滚转与位置、航向一起逐帧预测和校正。

保存独立炮塔方向与炮管仰角（快照第 13、14 索引）。底座固定；炮塔以有限角速度跟踪目标，对齐后开火。实时战场、星图、回放共享炮口变换。轰炸机优先攻击地面设施；真实弹体命中地面设施的舰体后产生约 18 秒的爆炸过程：初始火光和贴地冲击波、随后抬升翻卷的连续体积烟云、末期随风扩散和密度消散，特效不额外增加伤害。

大小防护盾发生器的现有护盾容量构成全阵地共享防护：所有同阵营地面设施（包含发生器自身）先消耗存活发生器的护盾，再扣目标自身护盾和耐久。多座发生器按实体顺序分担伤害，容量不重复复制给每座炮台；发生器死亡后立即停止贡献。舰船不借用地面护盾。沿用原有无战中再生、反物质绕盾及战略导弹独立结算规则。一个友蓝敌红的半透明护罩覆盖整个堡垒群，阵地扩建时自动扩张，能量耗尽或发生器全部毁坏后消失。

每个模块通过固定的 `fortressSlot.module` 统计所属设施。全部被摧毁时切换独立废墟几何：塌陷中央平台、焦黑地基、断墙、裸露钢筋及装甲碎片，关联通道同步破损。不另设建筑血量，也不因其他模块被毁而切换。状态从当前快照/回放帧派生，倒放可以恢复；缺少槽位的旧回放按原固定位置恢复归属。星图、实战、回放共用。

历史护盾与堡垒记录保存在 `output/playwright/fortress-state/`；对应独立测试已清理。

开发专用近地试玩启动器已移除。正式战场的“地面阵地”按钮仍可切换堡垒观察视角。
