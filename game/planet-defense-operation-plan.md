# 星球防守行动计划：能源提取

日期：2026-10-18  
状态：玩法与实施草案，仅记录计划，尚未实现。本文的建议默认值用于首轮验证，不代表已完成平衡测试。

## 1. 目标与原则

为单机半挂机游戏提供可预期、可准备、可自动完成的真实防守战，让玩家建造的炮台、护盾和驻军有长期用途。

- 平时经营、离线生产、普通刷野不会自行触发 AI 袭击。
- 玩家主动启动高收益行动，才承担这一次明确告知的来袭风险。
- 备战没有截止时间；风险从玩家确认启动后开始。
- 固定难度对应固定敌军，增加防御能真实降低战损，不按玩家战力同步抬高敌军。
- 自动战斗能够完成全部流程；手动驾驶与观战均为可选。
- 一次确认只授权一次行动，不自动续开，不因离线时长积累敌军。

本轮只写计划，不改游戏代码、正式存档、账号或运行服务。

## 2. 第一版范围

玩法暂名「能源提取」：玩家在本方星球启动高能提取装置，能量信号吸引深空敌舰。守住后获得资源，防线失守则本次行动失败。

| 项目 | 第一版建议 |
| --- | --- |
| 可选地点 | 本方普通行星；月球暂不参与 |
| 难度 | 三级固定档位：轻型骚扰、混合突击、重型攻坚 |
| 敌情 | 启动前公开舰种、数量、科技、波数与抵达时间 |
| 波数 | 每次一波，减少连续战斗修复与增援的复杂度 |
| 准备时间 | 不限时，浏览和调整方案不扣费 |
| 启动后预警 | 建议总计 3 分钟，包含集结与航行；可在数值验证后调整 |
| 并发限制 | 每个玩家最多一场未结束行动，跨星球共用 |
| 重复挑战 | 建议结束后冷却 60 分钟，跨星球、难度共用；无每日必做、连胜签到或次数过期 |
| 奖励 | 现有金属、晶体、气体；固定档位固定报价 |
| 战场 | 选定星球的真实近地轨道，使用现有炮台、护盾、舰队与战报 |
| 结束方式 | 自动结算、自动发奖，等待玩家主动开启下一次 |

第一版不增加独立可建造建筑、新货币、额外装置血条、多波生存、随机偷袭、仇恨值、全面宣战、领土占领或死星规则。

## 3. 玩家流程

### 3.1 选择与备战

从本方星球进入「防守行动」，选择档位。展示本次费用、奖励、敌军编成、预计抵达时间及风险说明。

同屏展示当前炮台、共享护盾、驻军，以及预警期间预计建成或抵达的增援。预计增援与已就位单位明确区分，不把排队中的单位算作现有防线。

玩家可以离开面板继续建造、调兵、搬走民用舰，或随时放弃方案。此阶段不生成来袭、不扣费、不产生冷却。重新打开时读取最新状态。

### 3.2 确认启动

启动面板直接说明：

> 启动后，敌舰将在约 3 分钟后抵达此星球。战斗会自动进行，关闭游戏也会结算。当地参战舰船与防御可能受损；行动失败不会掠夺主仓库或摧毁建筑。启动后不可取消。

服务端再次验证星球所有权、并发、冷却、资源和目标是否正在交战或存在已知敌对来袭。符合条件才原子扣除启动费用并创建行动；失败不扣费。

客户端提交预览版本和请求标识，服务端自行计算费用与敌军。报价过期则返回新预览，不按新价格静默扣费；重试同一请求不重复扣费或创建行动。

### 3.3 集结与来袭

行动开始时固定敌军编成、科技、随机种子、费用、奖励、目标和时间线。玩家升级、调兵或重新登录不会改变敌军。

星图展示「深空集结点 → 目标星球」及抵达倒计时。集结点只属于这次行动，不占用行星轨道，也不抽取或刷新现有 NPC 据点的守军。

到达前仍可正常调动舰队和建设。调整防线不延后抵达时间。启动后不允许取消、切换难度或改换目标。

### 3.4 自动交战

敌军抵达后，复用现有空间战斗、堡垒排布、地面共享护盾和自动索敌。防御设施与当地舰船真实参战，战斗期间建成、返航、部署抵达的单位按现有规则加入防守。

沿用现有驻军规则：当地民用舰也可能参战并损失，备战页必须提示玩家可提前转移。已经投入交战的单位不允许通过派遣重复使用或无损撤走。

敌方全灭且防守方获胜判定成功；防守方败北、双方全灭或达到现有战斗时限形成平局，均判定行动失败。第一版不通过无限拖延领取奖励。

### 3.5 自动结算

成功：返还幸存单位、结算战损与防御修复、一次性发放固定奖励、生成战报。

失败：返还幸存单位、结算战损与防御修复、无行动奖励、生成战报。敌方剩余部队撤离并从本次行动中清理，不继续攻击其他星球。

战报分别展示启动投入、奖励、舰船损失、设施损失、修复数量和永久损失；明确成功或失败原因，并提供只读回放。结束后进入冷却，离线时间正常计入冷却。

## 4. 防御的价值与数值方向

防御设施承担「让主力可以出门，同时守住收益」的作用。合理搭配的炮台和护盾应当能独立应对较低档行动；挑战更高档时，玩家可以补建防线或留下舰队支援。

| 档位 | 敌军方向 | 检验的建设能力 |
| --- | --- | --- |
| 一级：轻型骚扰 | 以轻型战机为主 | 基础炮台数量、覆盖与低成本独立守卫 |
| 二级：混合突击 | 战机与中型舰混编 | 火力搭配、共享护盾、少量驻军协同 |
| 三级：重型攻坚 | 重型舰与有限轰炸机 | 重火力、阵地抗压和主力支援取舍 |

- 编成只使用正式单位目录，不能把靶场专属舰型或试验数值混入正式玩法。
- 同档敌军数量和科技固定；初版不做隐藏随机编队，不因玩家造炮台而加强敌军。
- 玩家科技按现有战斗入场规则生效，不另加隐藏惩罚或胜负修正。
- 三档均可查看；只要满足基本启动条件即可自主选择，不以不可靠的「战力值」硬性判断能否挑战。
- 奖励与费用使用固定配置，不能实时按玩家矿产、库存或舰队规模缩放。
- 首轮平衡应证明：合理防线能够自动通关；加强防线有明显收益；驻军支援能降低风险；薄弱防线挑战高档会付出真实代价。
- 敌舰数量、科技、启动费用和奖励数额在隔离样本中测定。以相应发展阶段的生产收益、永久战损和挑战间隔计算净收益，不在计划阶段凭空确定最终数值。

## 5. 经济与战损边界

### 5.1 允许发生的损失

- 启动费用确认后扣除，成功或失败均不退还。
- 实际参战舰船可以被摧毁；防御设施按现有修复规则结算。
- 当前引擎对可修复的被毁防御逐座进行 70% 概率修复，并非每场保证返还 70%。界面不能承诺固定返还比例。
- 最大参战损失可达到全部投入单位，包括战斗中自动加入的增援；不把「仓库受保护」描述成整体无风险。

### 5.2 本次行动保护的内容

- 敌军不能通过这次行动掠夺普通仓库或恒星系共享库存。
- 不损毁生产建筑，不降低科技，不夺取星球，不毁月。
- 第一版没有中途产物：奖励只在成功结算时生成，失败无需扣除任何「预发奖励」。
- 行动产生的舰船损失不生成可回收残骸，也不参与造月。该限制双方一致，在预览与战报中明确，避免固定来袭成为额外刷残骸、刷月球渠道。
- 原本已有的残骸、普通任务和其他战斗结果保留原规则。

奖励调用现有 `depositResources` 入库，遵循恒星系共享仓储，沿用货物入库的溢出保留规则；满仓不会吞掉本次奖励，也不要求玩家赶上线领取。不增加新的奖励领取系统。

## 6. 离线、并发与异常处理

| 场景 | 预期行为 |
| --- | --- |
| 只打开备战页后下线 | 没有启动，就没有敌军或损失 |
| 确认启动后关闭页面 | 集结、航行、交战和结算继续；只完成已确认的这一场 |
| 关闭后台后重新启动 | 按持久化事件时间补算，与同条件连续在线结果一致 |
| 离线数天 | 最多补完一场；冷却可自然结束，不补发新敌军 |
| 重复点击、网络重试、多标签页 | 只创建一场、扣一次费、发一次奖 |
| 启动时目标正在交战或有已知敌对来袭 | 拒绝启动并说明原因，不扣费 |
| 启动后出现其他战斗，占用目标 | 行动敌军等待现有战斗结束，不并入他方攻击；显示等待原因和更新后的时间 |
| 行动交战期间另一支敌军抵达 | 沿用第三方任务排队，行动结算后正常释放；不能把其他攻击也套用仓库保护 |
| 战中生产、返航、部署、跳跃增援 | 复用现有单位占用和入场规则，数量与科技快照正确 |
| 目标消失或归属改变，且行动尚未交战 | 系统取消、退回启动费、无奖励、无冷却，记录原因 |
| 交战期间试图放弃目标或更换归属 | 禁止该操作，直到战斗完成，避免参战单位失去归属 |
| 战斗或结算出现异常 | 保留可恢复状态，不先标为已结算，不重扣费、不重发奖；修复后从持久化状态继续 |

后台重启不能重掷敌军、战损修复或奖励；回放不能调用行动推进与结算。行动完成后清理临时来袭实体，但保留战报和回放所需身份、时间线与配置快照。

## 7. 状态与实现位置

### 7.1 状态模型

备战是无费用的界面状态。确认后持久化行动：

```text
备战预览（不扣费）
  → 确认启动：扣费并保存配置
  → 集结 assembling
  → 航行 inbound
  → 交战 fighting
  → 成功 succeeded / 失败 failed
  → 冷却结束后可主动开启下一次

到达时目标被占用：inbound → waiting → fighting
交战前目标失效：assembling / inbound / waiting → cancelled
```

最小记录建议包含：行动 ID、请求标识、玩家与星球 ID、档位与配置版本、状态、固定敌军及科技、随机种子、启动时间、集结结束与抵达时间、费用与奖励快照、关联战斗 ID、结束与冷却时间、结算/退款标记、战报 ID。

以实际 ID 关联玩家和星球，不按名称识别。旧存档仅补充空行动集合，不自动开启玩法、不改既有进度；进行中的行动沿用启动时的配置。

### 7.2 后端

| 位置 | 计划职责 |
| --- | --- |
| 新增 `game/defense-operations.mjs` | 档位配置、预览、校验、行动状态、固定报价与行动结算规则 |
| `game/engine.mjs` | 在 `act`、`advance`、`snapshot` 接入行动；按事件推进；复用防守入场与第三方排队 |
| `game/spatial-battle.mjs`、`game/planet-defense.mjs` | 复用现有战斗、单位占用、共享护盾；按必要范围适配身份与战斗类型 |
| `game/system-logistics.mjs` | 复用扣费、资源入库；不另建第二套库存 |
| `game/battle-storage.mjs`、`server.mjs` | 校验行动状态、战斗检查点、回放与保存恢复的一致性；沿用现有认证入口 |

建议使用现有 `/api/action` 承接启动，状态通过 `/api/state` 下发，预览由服务端生成。最终 action 名称在实施时统一，不能信任客户端提交的敌军、费用、奖励或时间。

**结算必须显式分支。** 当前 `finishEngagement` 包含普通攻击掠夺、残骸、造月、返航和双方玩家战报，并假定进攻方存在于玩家集合。不能直接把行动敌军伪装成普通攻击任务后原样结算。

行动战斗须有明确的 `kind` 与 `operationId`；复用单位归还、损失统计、防御修复等共同逻辑，单独执行行动奖励与保护规则。敌方采用行动专属身份与元数据，不创建个人账号、不挪用现有 NPC 的库存或守军，也不能用无真实战损的 `trial` 模式替代正式行动。

结算时，单位归还、修复、奖励、报告、状态更新与排队任务释放应作为一次一致的世界状态更新保存。断电恢复只能落在结算前或完整结算后，不能从半个结果继续重复执行。

### 7.3 界面与星图

- 本方星球面板增加「防守行动」入口，备战页集中显示风险、敌情、费用、奖励和本地防线。
- 帝国/任务区域显示唯一进行中的行动，点击定位目标；不新增整页强制弹窗打断挂机。
- 复用星图中的航行表现、倒计时、近地战场和历史回放。敌军身份、目标、编成与服务端状态保持一致。
- 来袭显示阶段、抵达时间与波数；交战显示防守进度；结束显示结果和冷却。
- 信息以状态、通知和战报保留，不依赖音效或实时看见提示才能了解风险。
- 以当前正式入口为准接入 `client/command-p0/`、正式星球面板和 `scripts/universe/`；修改前核对实际源码与构建链，不仅改旧版 `client/` 或生成的 bundle。

## 8. 实施顺序与完成条件

### P1：规则、状态与存档

完成固定档位配置结构、服务端预览、启动校验、扣费、状态推进、冷却和空集合迁移。

完成条件：能够在隔离世界创建唯一行动、正确推进时间；重复请求与多标签页不重复扣费；未启动的世界长期推进不会生成来袭。

### P2：真实战斗与独立结算

接入行动敌军、防守单位、共享护盾、增援、行动结果、修复、自动奖励、战报和回放身份。处理普通任务排队及敌军清理。

完成条件：成功、失败、平局均能唯一结算；单位数量守恒；不发生仓库掠夺、额外残骸或造月；普通攻击原有规则继续生效。

### P3：备战界面与星图过程

完成选择档位、敌情预览、防线与增援展示、启动确认、来袭路线、战场入口和结果摘要。

完成条件：玩家从本方星球能完整完成一场；在不手动驾驶、不保持页面打开的情况下也能获得同样的有效结果；桌面及窄屏能读全核心风险与报价。

### P4：数值与离线验证

以薄弱防线、合理防线、加强防线、炮台独立守卫、舰队支援等样本验证三个档位。使用多个固定种子观察胜率、永久损失、修复波动与净收益。

对照逐步在线推进与跨时段离线补算，覆盖不同阶段的重启，以及跨过建造、增援、NPC 日刷新等事件的顺序。

完成条件：公布首版各档编成、科技、费用、奖励、预警时长与冷却的实际测试结果；防御投资能产生可观察的收益，低档不能成为无成本无限收益入口。

### P5：回归与交付

完成针对性单元/API/浏览器验证及相关原有战斗、经济、物流、保存恢复回归。更新玩法说明，并提供一次成功、一次失败、一次离线完成的验收证据。

完成条件：规则、界面提示、存档结果与战报一致；正式进度与账号未被验收修改；所有临时服务和测试数据已清理。

## 9. 验收清单与隔离要求

- [ ] 没有点击启动，长期离线也不会出现本玩法的敌军。
- [ ] 备战不限时，取消预览无费用；确认后费用、敌军、目标与奖励固定。
- [ ] 增加炮台或升级科技不会使同档敌军变强；合理防线可自动完成。
- [ ] 同一玩家跨星球、跨标签页最多一场；重复请求只扣费和发奖一次。
- [ ] 失败只产生已说明的启动费用与参战损失，普通仓库、建筑、科技、所有权不被本行动破坏。
- [ ] 幸存、毁损、修复、增援及库存数量可核对；民用舰风险与共享护盾效果符合说明。
- [ ] 满仓奖励完整保留；共享仓储不会重复扣费或重复入库。
- [ ] 战斗结束无额外残骸、造月或继续袭击；现有残骸和普通攻击规则不受影响。
- [ ] 普通战斗与行动互相排队能正常释放，不能借行动为其他战斗提供仓库保护。
- [ ] 关闭页面或后台重启只完成已确认的一场，无离线连打、重掷、重复奖励或重复修复。
- [ ] 目标失效按规则取消退款；交战目标不能被中途放弃；异常结果可恢复。
- [ ] 战报、快照、回放与实际资源和战损一致，观看回放不再次结算。
- [ ] 临时敌方身份清理后仍能读取历史战报和回放。

测试建议新增 `tests/defense-operations.test.mjs`、`tests/defense-operations-api.test.mjs` 和 `tests/defense-operations-browser.mjs`，围绕上述真实风险验证，不为纯展示文案增加镜像实现的测试。

严格遵守项目 `AGENTS.md`：

- `data/universe.json` 与 `data/session.json` 属于用户正式进度，不能用于创建测试账号或修改玩法数据。
- API/浏览器验收使用临时目录中的 `EMPIRE_SAVE_FILE`、独立 `EMPIRE_SESSION_FILE`、独立浏览器会话和明确的测试账号名称。
- 正式后台端口 `8289` 不用于测试、静态预览或演示。P0 界面预览固定使用 `8390`；API 测试另选空闲端口。
- 在 `finally` 中关闭本次启动的测试服务和浏览器上下文，删除本次临时账号、存档、会话、日志与战斗检查点；失败时同样清理。只终止自己创建的服务。
- 清理前核实绝对路径位于该次临时目录内。验收截图与汇总证据可以保存到 `output/`，不得包含个人正式存档或会话。
- 若未来确需迁移正式存档，先按账号 ID 核实原账号，并备份存档及其战斗检查点；不得按名称删除账号或重置资源、科技、舰队和战报。
