# P1 指挥工作台 · 独立测试页

预览地址：<http://127.0.0.1:8390/opendesign/mockups/p1-command-preview/index.html>

这一版先验收界面和交互，尚未接入正式游戏接口。沿用 P0 的深石墨、薄荷绿与琥珀色，以目录、模型、状态、操作面板构成工作区。

## 可试用范围

| 工作区 | 可操作内容 | 建议验收流程 |
| --- | --- | --- |
| 殖民地建设 | 14 个设施目录、分类搜索、模型旋转、固定建设区索引、升级前后对照、缺口和前置条件、当前施工 | 曙光升级金属矿 → 取消并退款；切换霜庭查看能源与资源不足 |
| 行星防务 | 炮塔与护盾目录、部署数量、模型、速射关系、批量生产、生产进度 | 建造两座等离子炮 → 60× 推进 → 查看部署数量；小型护盾限一座 |
| 舰队行动 | 三步派遣、任务目标、舰船数量、速度与装载、航线、来袭筛选、召回、运输往返 | 派遣大型货船运输 → 查看任务 → 召回；另试运输抵达与返航 |
| 帝国王庭 | 殖民地搜索与筛选、能源/来袭提示、批量发展模板、计划预览、计划排序与暂停 | 选择殖民地 → 发展模板 → 预览费用与目标 → 应用；打开建设计划调整顺序 |

页脚可以暂停时间、切换 1× / 20× / 60×、重置示例。桌面采用三栏工作区；窄屏改为纵向布局，殖民地表格保留横向滚动。

## 数据和边界

- 账号名称为“P1 界面测试”；四个殖民地、科技、库存、任务都是独立示例数据。
- 浏览器只保存到 `localStorage['galaxy-empire-p1-independent-v1']`。重置仅影响这一份示例。
- 设施/单位定义、费用与前置条件来自项目静态目录。模型与图像复制到本目录；来源见 `asset-sources.json`。
- 产量、施工时长、航程、燃料和模板为原型计算，不作为正式游戏结算依据。正式接入时全部以服务端校验和返回值为准。
- 运输可模拟卸货和返航；驻扎可模拟转移舰船。攻击、侦察、殖民、回收、探索和采矿只演示派遣与抵达，不执行战斗、奖励或殖民结算。
- 建设区是固定槽位索引，不提供自由放置。导弹属于后续 P2，不在本页生产。
- 服务只有静态白名单，拒绝 API、存档和源文件请求；不会访问 `data/universe.json`、`data/session.json` 或 8289。

## 启动与维护

双击 `打开P1测试页.cmd`，或在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File opendesign/mockups/p1-command-preview/start-preview.ps1
```

停止本预览使用 `stop-preview.ps1`。启动脚本不会停止未知的端口占用进程。8390 同时保留 P0 与 Three HUD 的显式预览路径。

修改 JSX 后重新构建；CSS 修改刷新即可：

```powershell
node opendesign/mockups/p1-command-preview/build.mjs
node --test opendesign/mockups/p1-command-preview/evidence/model.test.mjs opendesign/mockups/p1-command-preview/evidence/server.test.mjs
```

静态服务测试使用系统分配的临时端口，并在 `finally` 中关闭。没有创建游戏测试账号或存档。

## 正式接入顺序

1. 建设与防御：保留当前界面，将库存、前置条件、施工/生产队列与操作回执换成正式数据适配层。
2. 舰队：接入目标合法性、实际航程/燃料、任务队列与召回，删除原型结算计时器。
3. 王庭：接入殖民地汇总、发展模板和计划编辑；实际费用与可执行性由服务端校验。
4. 在独立端口、临时 `EMPIRE_SAVE_FILE` 和独立测试会话完成验收，再接入正式入口。

需要保留正式业务逻辑、现有 P0 入口和玩家当前操作状态。原型 `model.mjs` 仅供演示，不应整体搬入正式游戏。
