# 给 GPT‑6 Pro 的建模说明

把本说明、对应的 `briefs/编号-ID.md` 和 `images/编号-ID.png` 一起交给建模者。建议一次制作一类，先完成研究实验室，确认画风后再展开整套。

## 这套模型要长什么样

回到早期 AURORA：小星球上立着大而醒目的卡通太空设施。重点是大胆轮廓、清楚的功能和简洁色块，而不是写实建筑、满地小房子或密集机械碎件。

每类由一个鲜明主体和 3–5 个有实际用途的小型周边设施组成。主体约占整体视觉体量的三分之二；配套高低、宽窄有区别，紧凑地靠在旁边，通过短连廊、管线、输送带或装卸通道联系。保持主入口、装卸口和设备活动空间通畅。不要把周边设施全部吞并进主楼，也不要把它们排成等距棋盘。

- 米白外壳、深蓝灰结构、青蓝窗带和能源件，少量暖黄机械件；矿物、生态模块保留紫色与绿色的功能色。
- 大平面、少量倒角、低多边形曲面；保留图中立体高度，不压成一片低矮方块。
- 地面设施使用薄的局部基脚；浮空设施使用悬浮支撑，并留清晰离地间隙。不要统一铺成巨大方形地台，不添加一圈石头、树木或装饰杂物。
- 周边设施靠用途区分：水处理罐、样本舱、试验台、冷却器、货箱、维修棚各有不同形状。

## 看图与还原

以左侧大图决定造型、配套数量、相对位置、颜色和比例。右侧视图用于补充理解背面和布局。AI 生成的辅助视图存在透视、遮挡及局部细节差异，建模时将这些差异统一到同一个可信结构；不要把不同视图中的同一设施叠加成更多建筑。

太阳能设施按成图保留 **四片**大翼。Shipyard 上方轨道船坞是独立模块，不能照插图的摆放位置悬在地面园区侧上方；图中的断线表示电梯连接被压缩展示。

## 交付结构

每类保存独立、可编辑的模型源文件，并导出一个以原建筑 ID 命名的 GLB。整体根节点位于主体地基中心；浮空设施使用装配平台中央作为根节点，并记录离地基准。建筑、周边设施、连接件分别分组，统一坐标方向。保留适当尺寸比例，通过统一缩放接入游戏，不要分别压缩三个轴。

可移动部件单独建模并把枢轴放在真实关节处，例如雷达方位/俯仰轴、机器人肩肘夹爪、钻头和钻臂、太阳能翼铰链、电梯轿厢、吊机和吊具。样本球、晶圆、温室透明罩、星门效果面及在建舰体独立，方便动画或显示状态控制。

共享有限的基础材质，以色块和几何表现细节。不要把概念图的地面阴影或标题烘焙进模型。交付时给出实际三角面数、材质数，以及正面、侧面和游戏常用俯视角渲染，让用户直接比较图与模型。

## 与游戏对接时保留的关系

- 14 类行星设施和 4 类月球设施使用各自原 ID，概念名称不用于改游戏名称。
- `Metal_Storage`、`Crystal_Storage`、`Gas_Storage` 分别作为对应矿场的仓储子模块；不要把它们误认为缺少的独立园区。
- `Missile_Silo` 的场景表现是行星保障中心，以维修、后勤和封闭防务储存为主。
- `Shipyard` 分地面电梯组、缆线/轿厢、轨道船坞；`Flagship_Center` 是利用月球低重力的浮空重型船坞，中央悬浮半成品深空吞噬者（`Iron_Behemoth`）。舰体宽前窄后、前部双叉；船坞和配套全体离地，中央不设连续地板。半成品舰体独立，不替换现有成品舰船模型。
- 后续四种星球适配优先改变地基与支撑，保留同一设施主体和配套。气态星使用有悬浮支撑的功能浮台，矿体单独处理，不造假地面山体。
- 当前交付是独立模型参考。游戏 ID、升级、资源数值和个人存档不属于建模修改范围。
