你的工作是模型、材质、必要的演示地形、可关闭的设备动画与独立预览。游戏方负责模型接入、建筑 ID 映射、真实经营状态、完整镜头导航、大世界坐标、缓存与裁剪。本文不要求你修改或重建游戏，也不要求你验证游戏功能。

## 项目目标

资产将用于可以从银河连续接近到工业园区的科幻经营世界。远看星球有克制的灰蓝、沙褐配色、温柔云纹、干净晨昏线和蓝色大气；近看是真实尺度的地质地形与有生产逻辑的设施。星球始终庞大，建筑只是表面少量工业痕迹。独立预览只需展示你负责的资产，不必制作银河、游戏菜单、战斗或经营系统。

工业风格以露天矿区、化工园、港区、造船厂为结构参考。看到设施应该能辨认物料从哪里来、经何设备加工、在哪里储存、如何装卸。道路宽度、平台厚度、储罐尺度和管道连通应自洽。少用装饰性霓虹；可读性来自结构、明暗、少量安全黄和状态灯。不要做玩具城市、巨大水晶装饰、统一圆形凸台或球面均匀铺满的积木。

## 尺度与方向

- 工业资产使用自己的模型坐标，`Y` 向上，地面原点为 `[0,0,0]`，普通场地约 `6 × 4` 模型单位。矿区可扩大占地，但请声明实际尺寸。这里是相对比例约定，不把一模型单位声明为一米。
- 独立制作建筑群时，只需一个局部地面或矿坑，无须造完整星球。为方便比例判断，同一模型坐标下类地星的参考半径为 `1600`：普通设备在星球上应该非常小。不要为从轨道看清单体而把设备放大。
- 若制作星球模块，默认半径为 `175` 星球显示单位。游戏方会把工业模型统一缩放为 `175 / 1600 = 0.109375`；作者在工业资产内部保持缩放为 1，不必实现这次接入变换。
- 交付模型的局部包围盒、地面占地多边形和主要锚点。细节集中在可见设备，不必为毫米级零件增加整颗星球的网格密度。
- 工业资产按局部平面制作，星球资产按球心局部坐标制作。贴合星球、自转跟随与相机相对原点由游戏方处理；材质应允许改变光源和观察方向。

## 资产与预览分离

交付至少包括 `asset.js`、`preview.html`、`preview.js`、简短 README，可整体打包为 ZIP。`asset.js` 只导出模型生成函数；独立预览当然可以有自己的渲染器、相机、交互、动画循环和模拟数据，把这些放在 `preview.js` 即可。这样游戏方拿到文件后可以提取模型，无须移植整个演示页面。

只有资产文件不能创建 renderer、canvas、RAF、全局输入监听或请求游戏接口。加载资产文件本身不会自动打开演示。若生成环境更适合单个 HTML，也可以交付 HTML，但必须把模型工厂与预览启动代码分成清晰、独立的模块，并同时导出资产 JS。

作者自己的目录即可运行，不需要游戏项目已有的 `node_modules`。优先使用 Three.js `0.184.0`，在交付目录中附带预览所需的本地模块与许可证，或附完整依赖清单和安装/启动步骤；说明运行前是否需要安装依赖。运行时默认不依赖 CDN、远程纹理、远程字体、API 或账号。程序化材质为主，必要的本地资源一并交付并说明版权。资产通过参数接收 `THREE`，或使用标准 `import * as THREE from 'three'`，由游戏方适配。

推荐的最小工业接口如下。函数名可以调整，只要 README 写清用法；这不是现有游戏 API，不需要寻找对应源码：

```js
export function createIndustrialAsset({ THREE, type = 'metal', seed = 17 }) {
  return {
    root,                          // THREE.Group，模型局部坐标
    groups: { terrain, structures, equipment, effects, silhouette },
    anchors: { ground, view },     // 可按模块补充装卸、停靠、电梯端点
    footprint,                     // [x,z] 顶点组成的占地边界
    bounds,                        // 模型局部包围盒
    setVisualState({ running = true, activity = 1, construction = 1, storageFill = 0.5 }) {},
    update(dt, { visible, detail }) {},
    dispose() {}
  };
}
```

约定 `footprint` 是 `[[x,z],...]`，`bounds` 是 `{min:[x,y,z],max:[x,y,z]}`；每个锚点是 `{position:[x,y,z],normal:[x,y,z]}`，均相对于 `root`。`dt` 以秒计，`visible` 为布尔值，`detail` 为 `'near'` 或 `'far'`。

演示参数含义：`running` 控制设备启停；`activity` 为 0–1 的工作速度；`construction` 为 0–1 的视觉完成度；`storageFill` 为 0–1 的库存显示量。预览可以用滑块和固定假数据展示，不需要连接真实等级、资源或生产队列。正式游戏如何对应施工、升级、低电力、仓满、停工，由游戏方处理。隐藏和远景时停掉精细动画，不自行产生资源或执行游戏规则。

## 性能和颜色

重复储罐、支架、管件、设备和太阳能板使用共享几何、共享材质及 `InstancedMesh`。不要给每个小零件附加光源。高细节建议每个综合体不超过 60 个 draw calls、15 万三角形；远景简化到 1–4 个 draw calls。交付实际计数，不以这些建议数字代替测量。

优先用 Three.js 标准材质。预览可以设置曝光和色调映射，但不要把它写死在资产模块里。若使用自定义 `ShaderMaterial`，支持 Three.js 对数深度，避免重复 Gamma/ACES；大气透明层不写深度。提供 `dispose`，只释放本模块拥有的资源，不销毁传入的共享资源。
