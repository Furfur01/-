# 可直接转发：大尺度类地星与地形样板

请独立制作一个 Three.js 程序化星球模型与局部地形样板，交付可运行代码、独立预览和说明。你看不到游戏项目，也不需要任何项目文件、旧模型、账号或 API。本文包含所需视觉基准和尺度约定；按本文即可开始。

你只负责星球与地形资产、材质、必要动画和预览。游戏方负责接入正式世界、完整导航、建筑映射、战斗规则、大世界坐标与资源管理。预览只需一个星球和少量比例参照物，不必制作银河、工业建筑群或经营系统。

## 视觉方向

远景采用本文下方给出的程序化着色基准：六层分形噪声、纬度条带、灰蓝与沙褐的混色、浅米白云纹、柔和晨昏线、蓝色边缘散射和独立透明大气壳。它已将我们所说的“融合靶场风格”写成可用公式，你不需要看到靶场文件，也不需要寻找任何项目着色器。画面克制、干净，有球体的重量与纵深；不使用照片拼贴或平面圆形贴图。

从轨道连续接近地面后，同一地貌细化为宽广平原、山脉、沉积层、矿床、海岸或干涸河谷。不要靠近时替换成另一颗卡通星球。地形配色、种子和高度函数在所有 LOD 保持一致。低地和山脉要有大区域结构，不要把全表面做成均匀噪点。

请以以下完整噪声函数和着色表达式作为远景基准，允许优化实现，但保留其配色和光照气质。表达式需放入你编写的 Three.js 材质，不是可直接运行的整段 shader：`N` 为星球局部径向单位法线，`W` 为变换后的世界单位法线，`sunDirection` 为表面指向光源的世界单位向量，`viewDirection` 为表面指向相机的世界单位向量。

```glsl
float hash3(vec3 p) {
  p = fract(p * .3183099 + .1); p *= 17.;
  return fract(p.x * p.y * p.z * (p.x + p.y + p.z));
}
float noise3(vec3 x) {
  vec3 i=floor(x), f=fract(x); f=f*f*(3.-2.*f);
  return mix(
    mix(mix(hash3(i),hash3(i+vec3(1,0,0)),f.x),
        mix(hash3(i+vec3(0,1,0)),hash3(i+vec3(1,1,0)),f.x),f.y),
    mix(mix(hash3(i+vec3(0,0,1)),hash3(i+vec3(1,0,1)),f.x),
        mix(hash3(i+vec3(0,1,1)),hash3(i+vec3(1,1,1)),f.x),f.y),f.z);
}
float fbm(vec3 p) {
  float amplitude=.5, value=0.;
  for(int i=0;i<6;i++){ value+=amplitude*noise3(p);p*=2.1;amplitude*=.5; }
  return value;
}
// N 是星球局部径向法线，W 是正确变换后的世界法线。
float bands=fbm(vec3(N.y*9.,N.x*1.3,N.z*1.3)+fbm(N*4.)*1.5);
vec3 color=mix(vec3(.16,.21,.32),vec3(.55,.42,.3),smoothstep(.35,.7,bands));
color=mix(color,vec3(.75,.7,.62),smoothstep(.62,.8,fbm(N*7.+2.)));
float light=dot(W,sunDirection);
float rim=pow(1.-max(dot(W,viewDirection),0.),3.);
vec3 linearColor=color*smoothstep(-.15,.6,light)
  +vec3(.25,.55,1.)*rim*smoothstep(-.3,.4,light)*1.4;
```

大气可参考背面球壳上 `r=smoothstep(0.,.33,max(dot(-W,V),0.))` 与 `l=smoothstep(-.4,.5,dot(W,sunDirection))` 的乘积。进入大气和背面观察时也要稳定；透明层不写深度。切勿直接拿局部法线与世界光照相乘。

## 尺度与地形

星球默认半径为 `175` 显示单位。为了检查尺度，预览中可以放一个长 `0.65625`、宽 `0.4375`、高 `0.2` 显示单位的朴素盒子，代表普通工业场地中的设备范围。它在轨道远景里应当很小，只有靠近地表才能看清；不需要为了看清盒子把它放大。这些尺寸已给齐，不需要了解旧版游戏或换算历史模型。

比例参照物只占星球少量位置。选择地势平缓、有地质依据的地点；必要时整地应过渡到周边天然地形，不要做统一凸起圆台。提供地形查询函数，使参照物和地形使用同一高度。另保留一块可参数化的平缓区域作为接入预留：默认中心方向 `[1,0,0]`、角半径 `0.01` 弧度，中心高度为 0，边缘平滑过渡。你不需要实现碰撞、登陆或战斗系统。

## 代码交付合同

交付 `planet-asset.js`、单独的 `preview.js` 与 `preview.html`、README，可打包为 ZIP。优先使用 Three.js `0.184.0`。附预览所需的本地模块和许可证，或给出完整依赖清单与安装/启动步骤；运行时默认不依赖 CDN、远程素材或网络 API。你的目录应能独立运行，不需要游戏方的文件或 `node_modules`。

```js
export function createPlanetAsset({
  THREE, seed=17, radius=175, biome='terrestrial',
  flatRegions=[{direction:[1,0,0], angularRadius:0.01}]
}) {
  return {
    root, // 不带独立 Scene/Renderer，相机和自转由宿主控制
    groups: {globalTerrain, nearTerrain, clouds, atmosphere},
    heightAt(direction) {}, // 星球局部单位向量 -> 高于基准半径的世界单位
    normalAt(direction) {},
    surfaceAnchor(direction) {}, // {position:[x,y,z],normal:[x,y,z]}，星球局部坐标
    setLighting({direction}) {}, // 指向光源的世界单位向量 [x,y,z]
    update(dt,{eyeLocal,visible,detail}) {},
    stats, // {triangles,drawCalls,cachedPatches}，注明测量条件
    dispose() {}
  };
}
```

`direction`、`eyeLocal` 和返回位置使用三元素数组；`dt` 以秒计，`visible` 为布尔值，`detail` 为 `'near'` 或 `'far'`。固定种子必须同时影响地形、颜色和云纹，而且重复生成结果一致。若采用不同函数名或对象类型，在 README 中给出完整调用示例即可；这不是需要查询的游戏 API。

资产工厂只生成对象，不创建 renderer、canvas、RAF，不注册全局事件。独立预览可以创建自己的 renderer、相机、灯光、循环和操作按钮，展示靠近、环绕、自转、顺光和逆光。无需实现银河级坐标变换，游戏方会处理。标准材质优先；自定义 `ShaderMaterial` 支持 Three.js 对数深度，避免重复手动 Gamma/ACES。曝光和最终显示转换由预览统一设置，不能写死在资产里。

交付一个低细节全球球体与一个可定位的高细节局部地块样板，两者来自同一高度函数、种子与配色。地块边缘提供接缝或裙边，预览接近时平滑显示。只细化当前观察区域；如果实现了地块缓存，注明上限。Worker 可选，如使用只返回顶点、法线、索引数组。游戏方会接入正式加载队列、资源缓存和裁剪，你不需要复制游戏的调度系统。

## 验收与变体

提供固定种子 17、42、101 的全星球、轨道与近景图。在独立预览中观察晨昏线、极区、背面、大气内外、快速放大和反向缩小；说明是否有接缝、闪烁或已知限制。报出三角形数、draw calls、局部地块数量和释放方法。无需接入游戏或完成游戏的 30 次导航验收。

首批重点完成 `terrestrial` 类地星与近景地形。保留 `biome` 参数，并注明后续如何扩展 `mercury` 岩质星、`mars` 火星型、`gas` 气态星、`moon` 月球：气态星以云带与风暴为主、无可见固态地表，月球几乎没有大气。首批不用完成其余四种精修模型。最终请同时交付可提取的资产代码与独立预览，不能只交截图。
