# 可直接转发：独立制作完整首都综合区与月球前哨

请用 Three.js 独立制作一座科幻工业殖民地的首都综合区，补齐行政、科研、制造、能源、通信、后勤和行星维护设施。交付可编辑模型生成代码、材质、可关闭动画、独立预览与说明。你不需要访问游戏项目、源码、账号或接口，本文就是完整制作任务。

首都是一片连续、有边界、有道路和功能分区的城市级资产。每个功能都有独立可提取的建筑组，游戏方将分别映射到已有建筑项。不要把所有功能合并成一栋万能大楼，也不要把十种建筑摆成彼此无关的展台。它们在空间上是一座首都，在数据上仍可分别控制。

你的工作是美术资产与预览。游戏方负责正式建筑 ID、真实等级、资源和生产规则、点选、镜头、球面坐标与缓存。预览可以自行使用假数据、灯光、相机和动画循环。

## 1. 城市构图

整体采用工业写实的科幻殖民地语言：混凝土、旧钢、浅灰与暗蓝灰建筑、少量安全黄、克制的暖色窗光。城市具有行政秩序和生产能力，设备、道路、结构与检修方式可信；避免玩具积木城、纯装饰宫殿、满屏霓虹和平均铺满的高楼。

核心由一个可辨识的主基地、行政广场和通信地标组织。科研院区位于较安静的一侧，制造街区靠近货运干道，能源、公用工程与地形作业位于外围，后勤与保障区靠近出入口。用一条主轴、若干支路和环形服务道路把这些区域连成整体。

保持主次：主基地有清楚轮廓，科研院区有成组中低层建筑，制造区有大跨度车间，能源区有大尺度但低密度的场地。各区之间留出道路、广场、管线、空地和扩建余地；不要每格都摆相同数量和大小的建筑。

主干道路必须通向外部矿业园区和太空港的预留接口。独立模型只需道路、轨道或管廊的连接口与短延伸段，不必复制矿场或电梯。可以布置少量宿舍、食堂、维修、消防、停车等视觉配套，这些只是环境建筑，不代表新增游戏经营项目。

## 2. 十个必备功能模块

下列 key 是本次独立资产的通用名称，不是要求你查询的游戏 API。每个模块都应有主设施、配套体块和可辨识的工作空间；建筑数量以形成完整街区为准，不用大量复制小零件凑数。

| key | 功能与外观要求 | 建议位置 |
| --- | --- | --- |
| `command` | 主基地与行政指挥中心：指挥主楼、接待或行政附楼、通信屋顶、入口广场和车辆到达区。作为首都视觉中心，避免巨型王宫。 | 中心主轴 |
| `research` | 科研院区：数座实验楼、试验厂房、数据与分析设施、封闭连廊、小型试验场。材料、建筑与开放空间有学院式组织。 | 核心侧翼 |
| `robotics` | 机械制造园：大跨度装配车间、机械臂工位、零件仓、转运与检修区，装卸口朝向物流道路。 | 制造街区 |
| `nanofab` | 精密制造与纳米工厂：洁净厂房、设备层、气体与过滤配套、封闭物料通道。比普通机械厂更封闭、紧凑且精细。 | 与机械制造相邻 |
| `solar` | 太阳能场与电力配套：成片有检修通道的面板或集光设备、逆变与变电设施、出线管廊。板阵可以重复，但需要明确阵列分区与维护入口。 | 城市外缘开阔地 |
| `fusion` | 聚变能源区：反应装置主厂房、涡轮或能量转换配套、换热冷却、控制与输配电区。用设备组合表达能源设施，不靠发光球代替工厂。 | 外围公用工程区 |
| `radar` | 行星通信与探测区：大型天线阵列、接收和控制楼、维护空间、明确的天线旋转净空。 | 外围开阔或略高位置 |
| `allianceLogistics` | 联盟协作与接驳区：联盟联络主楼、会议与通信设施、协作调度、访客和后勤到达区。体现多个殖民地的协作联系，外部道路通向港口方向。 | 行政区靠对外入口一侧 |
| `terraforming` | 地形改造与环境工程区：泵站、处理塔、管网控制、施工机械、试验或整地区域。主设备可见，外围作业地形平滑过渡。 | 城市边缘施工方向 |
| `planetarySupport` | 行星保障与防务仓储区：维修车间、调度楼、应急车辆、受保护的物资储位和小型防务附属设施。主体表现维修后勤，不把整个城区做成武器展览场。 | 外围服务道路旁 |

建议组织为五个相连城区：行政科研、制造、能源公用工程、通信环境工程、后勤保障。十个功能模块均需单独命名和定位；同一区内可以共享道路、管廊和公共配套。

## 3. 首都的边界、入口和地形

外部要能一眼看出城市在哪里开始和结束。围栏或低墙、周界道路、排水、护坡与裸土缓冲组合成完整外缘，保留主要入口和货运入口。能源阵列和地形作业区可以沿外缘展开，但仍有清楚占地和连接关系。

主入口具有门岗、标识、道路分流与到达空间；货运入口连接编组或仓储，不让重型运输穿过行政广场。城市内部用道路、铺装、绿地或裸土、管廊和建筑形态区分城区，不必每个街区再砌一圈围墙。

场地可以是有秩序的正交布局，但地形不应是一张漂浮厚底板。边缘铺装接碎石、裸土、护坡和自然地形；道路出园处有短延伸段，其他地方不留下被截断的悬空路面或管线。最终接入球面由游戏方完成，你只需提供局部地形和高度查询。

## 4. 尺度与方向

采用 Y-up，X/Z 为地面，首都地面原点为 `[0,0,0]`，`root.scale` 保持 `(1,1,1)`。这里使用相对模型单位，不宣称一单位等于一米。普通运输车长约 0.35–0.6、宽约 0.15–0.25 模型单位，门、栏杆、层高和车道都与之匹配。

首都可从约 `60 × 44` 模型单位的总场地开始规划，按合理布局调整并报告实际占地。普通设备保持尺度，通过增加街区、道路和配套形成城市，不能把单体整体放大来充数。能源场和环境工程可单独向外延伸，但要计入边界。

若需要理解远景比例，同一模型坐标下参考星球半径为 1600；无需在预览中创建它。实际星球比例与缩放由游戏方适配，首都从轨道观察时应是地表的一片小型建设区。

## 5. 模型工厂与独立状态

交付 `capital-asset.js`，导出例如：

```js
export function createCapitalAsset({
  THREE, seed = 17, size = {width: 60, depth: 44},
  ground = {heightAt: (x, z) => 0}
}) {
  // 在这里创建模型，不能自动启动预览。
  return {
    root,
    groups: {terrain, perimeter, roads, utilities, districts, effects, silhouette},
    modules, footprint, siteBoundary, bounds, anchors,
    heightAt(x, z) {},
    setModuleState(key, state) {},
    update(dt, {visible = true, detail = 'near', animate = true} = {}) {},
    dispose() {}
  };
}
```

这是交付接口示意，代码内部结构可自由实现，但请在 README 给出实际调用方法：

- `modules` 为按十个 key 索引的对象。每项含独立 `root: THREE.Group`、局部占地 `footprint`、根组局部包围盒 `bounds` 和 `{ground, view, entry}` 锚点。主模型包含各模块，不能为每个模块另建 renderer 或 canvas。
- 总体 `footprint` 是包括边缘地形的外包占地 `[[x,z], ...]`；`siteBoundary` 是主要城市围界的有序顶点。`bounds` 为 `{min:[x,y,z],max:[x,y,z]}`。
- 总体 `anchors` 包含 `mainEntry / cargoEntry / mineRoad / spaceportRoad / commandView`。每项为 `{position:[x,y,z],direction:[x,y,z],width}`；观察锚点可省略 width。方向为单位向量，位置均相对首都根组。
- `heightAt(x,z)` 返回整地后高度，使用模型单位；模型基础和道路以同一高度为准。
- `setModuleState(key,state)` 接受 `{visible:true,running:true,activity:1,construction:1,storageFill:0.5}`。visible/running 为布尔值，其余为 0–1；仅控制单个模块外观和设备活动，不改变其他区的状态。
- 未建成或施工状态可显示预留场地、基础和脚手架；改变一栋功能模块时仍保留公共道路和相邻城区。不要依赖十个模块永远全部存在。
- `update` 的 dt 为秒，detail 为 `'near' / 'far'`。隐藏、远景或动画关闭时停止精细设备、车辆和粒子更新。
- `dispose()` 只释放实例拥有的资源，正确处理共享几何、材质与实例化对象。

可以给物体加通用 `moduleKey` 以便识别，但不需要实现正式游戏的选择、升级、资源或生产逻辑。预览可使用滑块、开关和模拟数据检查独立状态。

## 6. 月球专属前哨扩展

另交一套规模更小、沿用相同材质与接口的月球前哨，包含以下三个独立模块。它们不摆进普通星球首都，预览中单独切换到月球样板即可。

| key | 必备结构 |
| --- | --- |
| `moonBase` | 月球基地：加压舱段、气闸、对接廊、生命维持与就地防护结构，贴合无大气岩质地面。 |
| `lunarRadar` | 月球雷达：大口径阵列或分布式天线、控制舱与维护路线，轮廓区别于普通星球的通信区。 |
| `jumpGate` | 跃迁设施：有明确通行空间的大型门架或环形装置、供能与控制配套、到达和离开锚点；作为视觉模型，不实现传送规则。 |

提供 `createLunarOutpost({THREE,seed,ground})` 或等价独立工厂，三个模块分别可提取和控制。前哨共享局部地形、服务通道与管线，不必重复建完整普通星球首都；设备尺度与首都保持一致。

## 7. 预览、性能与交付

交付资产 JS、独立 `preview.js / preview.html`、README 和需要的本地资源。优先 Three.js `0.184.0`，附本地 ES Module、所需 addons 与许可证，或完整依赖和安装启动说明。运行时默认不依赖远程模型、纹理、CDN、账号或游戏 API。

预览可以有自己的 renderer、scene、相机、灯光、鼠标控制和 RAF；资产文件本身只导出工厂。允许轨道旋转、拉近城区、切换固定种子 17/42/101、切换光照、显示分区和边界、逐模块开关和调节施工/活动状态。无需重做游戏界面或银河导航。

重复厂房构件、面板、围栏、管件和车辆尽量共享几何材质或使用 InstancedMesh，但保持模块能独立控制。提供全城轮廓、城区体块和近景细节的区分，报告各档 draw calls、三角形和动画对象数。不要为每盏窗灯、焊点都创建真实光源。资产不修改全局曝光和色调映射。

至少提供：全城斜俯视、标注十个功能的总平面、主入口、行政科研街区、制造物流街区、能源与边缘地形近景，以及月球前哨总览。再录一段独立预览中的全城到城区环绕，展示布局能从多个方向成立。

验收重点：十种普通星球功能和三种月球功能齐全；首都具有中心、分区、公共连接与清楚边界；设备比例一致；功能模块独立控制而公共空间保持连贯；拿走预览程序后仍能单独导入模型。数量增加要体现在功能和城市组织上，不以重复生产线数量替代缺失建筑。
