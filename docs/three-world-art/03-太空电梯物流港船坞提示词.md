# 可直接转发：独立制作太空电梯、物流港与轨道船坞

请用 Three.js 独立制作一套太空电梯资产，包含地面物流港、缆索、升降舱和轨道船坞，交付模型生成代码、材质、可关闭动画、独立预览和说明。**你不需要访问任何现有项目、游戏源码、游戏 API 或现有函数，本文就是完整任务。** 重点是把地面物资运上轨道、进入船坞装配、再由舰船离港的结构与流程做清楚。

你负责模型、材质、局部地面、设备动画和独立演示。我们负责正式游戏接入、建筑 ID 映射、真实生产状态、镜头路径、大世界坐标、球面定位、自转和运行时裁剪。无需实现游戏队列、舰船规则、星图或整颗星球；演示可使用你制作的简化舰体。

## 结构与美术

**地面港**：设置公路或铁路卸货、仓储、集装箱分拣、升降装载区、控制室和检修设施。物资从入口到仓储、再到升降舱的路线连贯，有车辆转弯、吊装和维修空间。两条或多条缆索有明确锚固和受力基础，避免巨大装饰底盘遮住全部结构。普通设备细小可信，港区靠流程展开形成规模。

**升降区**：区分上行、下行和维护路线。舱体与缆索导向结构相配，有停靠装载、出发、上升、减速、轨道卸载、下降和返港过程。货箱不穿过站体，进入站点前对准停靠位置。可以用主受力束和维护通路表达缆索，不要求把每根钢丝做成独立重几何，也不需要真实轨道或缆索动力学。

**轨道船坞**：使用开放桁架和装配腔，避免闭合球壳。包含龙骨定位、装甲分段、推进模块、机械臂、物资暂存、检修通道和离港口。中间装配区保持净空，舰船沿明确轴线出入；机械臂和桥架不能堵住出口。少量安全灯标说明边界，避免彩灯堆积。简化演示舰体也要区分龙骨、外壳和推进器，以便展示装配阶段。

主色为旧钢、浅灰、暗蓝灰和少量安全黄。钢材、涂层、混凝土和橡胶有不同粗糙度，磨损适量。顺光能读出设备层次，逆光有清楚的桁架轮廓，夜景靠少量灯具、灯标和窗口说明尺度。不要做玩具太空站、巨大装饰晶体或满是霓虹的观光塔。

地面港应有围界、外围服务道路、明确的公路/铁路进出口和地形收边，使仓储、编组、升降核心与维修区形成完整港区。轨道部分保留开放结构，用平台边缘、检修走道、灯标、停泊门架和装配净空划定作业范围；各船坞通过运输桁架连接中央物流节点。边界在斜俯视中也要读得出来，不能只依靠地板外沿或包围整个站体的外壳。

## 模型尺度与分组

采用 **Y-up**，地面锚点为 `[0, 0, 0]`，地面港位于 X/Z 平面，初始占地 **6 × 4 模型单位**。模型单位不宣称等于一米，保留 `root.scale = (1,1,1)`，无需理解未来游戏的尺度换算。如需比例参考，同一模型坐标下的星球半径为 1600；不要求创建星球，最终放缩由我们负责。

`stationHeight` 默认 **240** 模型单位，表示从地面原点到轨道站连接点的 Y 向高度，不是现实同步轨道的物理计算。改变高度时只改变缆索长度、升降路径和站点位置，普通设备不能整体随高度放大。预览至少能切换 120、240、360，检查连接和动画是否仍然正确。

普通运输车可长约 0.35–0.6、宽 0.15–0.25 模型单位；集装箱、门、栏杆、舱门和检修梯保持一致比例。货舱容得下货箱，道路容得下运输车，船坞净空容得下演示舰体。船坞可以大于地面港，但要说明包围盒与可用净空，不能为全景效果将普通设备也拉到巨型尺度。

地面港、缆索、轨道站、升降舱、装配设备和特效分别成组，并报告各组包围盒，方便我们接入独立裁剪。你不需要实现全银河、星球地平线或大世界裁剪；预览提供分组开关便于检查即可。

## 独立资产接口

交付 `space-elevator.js`，导出 `createSpaceElevator(options)`。全部参数含义如下：

- `THREE`：预览传入的本地 Three.js 模块。
- `seed`：整数随机种子，用于稳定布局和细节。
- `stationHeight`：站点连接点的局部 Y 坐标，默认 `240`。
- `portSize`：地面港 X/Z 方向尺寸，默认 `{width: 6, depth: 4}`。
- `dockClearance`：船坞内可用净空盒尺寸，默认 `{width: 3, height: 2, length: 8}`；宽沿 X、高沿 Y，规定 `+Z` 为离港方向。
- `ground`：`{heightAt(x,z)}`，输入地面高度函数，返回模型单位，默认 `() => 0`；只用于地面港基础和整地。

完整独立调用示例：

```js
import * as THREE from './vendor/three/three.module.js';
import {createSpaceElevator} from './space-elevator.js';

const asset = createSpaceElevator({
  THREE,
  seed: 42,
  stationHeight: 240,
  portSize: {width: 6, depth: 4},
  dockClearance: {width: 3, height: 2, length: 8},
  ground: {heightAt: (x, z) => 0},
});

asset.setVisualState({
  running: true,
  activity: 0.8,
  construction: 1,
  storageFill: 0.6,
  assemblyProgress: 0.45,
  showDemoShip: true,
});
asset.update(1 / 60, {
  groundVisible: true,
  cableVisible: true,
  stationVisible: true,
  detail: 'near',
  animate: true,
});
// 预览将 asset.root 添加到自己的 scene；不用时先移除，再调用 asset.dispose()。
```

返回值包含下表内容，所有字段都是独立模型数据：

| 返回项 | 约定 |
| --- | --- |
| `root` | 一个 `THREE.Group`，包含全部资产，以地面锚点为局部原点，缩放保持 1。 |
| `groups` | `{groundPort, cables, station, cabins, shipAssembly, effects, silhouette}`；每项为命名的 `THREE.Group`，空组也保留。 |
| `footprint` | `[[x,z], ...]`，包围地面港和局部地形的占地多边形，至少 3 点，不重复终点。 |
| `bounds` | `{min: [x,y,z], max: [x,y,z]}`；整个模型实际局部包围盒，含机械臂、舱体和演示舰体最大运动范围。 |
| `groupBounds` | 与 groups 同名的对象，各项为 `{min: [x,y,z], max: [x,y,z]}`，坐标统一相对根组；空组可返回 null。 |
| `anchors` | `{ground, viewGround, viewStation, cableBottom, cableTop, station, dock, departure}`；每项为 `{position: [x,y,z], normal: [x,y,z]}`，normal 为单位向量，全部使用根组局部坐标。 |
| `cableAnchors` | 数组，每条主要缆索一个 `{bottom: [x,y,z], top: [x,y,z]}`，端点与模型一致，升降动画也使用这些路径。 |
| `dockAccess` | `{up: [0,1,0], clearanceRadius}`；up 与 dock/departure 的离港方向垂直，clearanceRadius 是实际通行半径，以模型单位计。 |
| `heightAt(x,z)` | 查询整地后的地面港表面高度；基础与道路使用同一结果，不包含空中缆索和站体。 |
| `setVisualState(state)` | 接收下述外观参数，不创建真实生产队列或资源。 |
| `update(dt, options)` | dt 为秒，options 为 `{groundVisible, cableVisible, stationVisible, detail, animate}`；四个开关为布尔值，detail 为 `'near' / 'far'`，默认全部开关 true、detail 为 near。 |
| `dispose()` | 释放实例拥有的几何、材质、纹理等资源，可安全重复调用，共享资源应正确处理引用。 |

ground 的 normal 是基础向上法线；viewGround/viewStation 是推荐观察位置，normal 指向展示主体；其余锚点的 normal 为连接或离开方向。cableBottom/cableTop 是整组缆索的中心连接点，单条端点另由 cableAnchors 提供。dock/departure 描述同一条离港轴线，dockAccess 报告其净空。station 锚点的 Y 坐标就是 stationHeight。

`setVisualState` 的通用默认参数为 `{running: true, activity: 1, construction: 1, storageFill: 0.5}`。running 为布尔值；其余三个为 0–1，表示设备活动强度、设施施工展示进度、仓储和货箱填充程度。本资产可增加 `assemblyProgress: 0`（0–1，示范舰体装配进度）与 `showDemoShip: false`（布尔值，显示示范舰体）。这些参数不依赖真实队列、等级或游戏事件，我们后续负责映射。

预览可以自行模拟循环运输、装配和离港，标为演示即可。assemblyProgress 控制装配阶段，资产本身不擅自把它推到完成；预览可以用滑块或模拟脚本改变它。showDemoShip=false 时保留船坞设备并隐藏示范舰体，方便我们放入其他模型。

running=false 或 animate=false 时停止作业；activity 可降低升降和设备速度。隐藏对应分组或切换远景时停止不必要的机械臂、焊接、粒子和精细设备动画，恢复时不补播历史帧。升降舱按所在区域控制显示，不要因为地面港关闭就把所有空中舱体一起删除。

**资产工厂与独立预览分开。** `space-elevator.js` 不创建 renderer、canvas、相机、RAF 或全局输入监听，导入时不自动启动。`preview.js` 可以自行创建场景、相机、renderer、循环、鼠标控制和模拟状态 UI。你不需要接入既有镜头路径或渲染器，我们后续提取工厂完成正式集成。

## 独立预览与交付

默认完全离线。交付 `space-elevator.js`、`preview.js`、`preview.html`、所有本地材质资源、README，以及本地 Three.js 依赖。默认 **Three.js 0.184.0**，`vendor/three/` 包含实际使用的 ES Module、`three.core.js`、所需 addons 和许可证，并说明完整依赖清单。不要依赖作者或接收者能访问项目 node_modules，不使用 CDN、远程纹理、远程模型、登录或网络 API。

README 写清版本、文件结构、本地静态 HTTP 启动步骤和浏览器地址。例如已装 Python 时在交付目录运行 `python -m http.server 8000 --bind 127.0.0.1`，打开 `http://127.0.0.1:8000/preview.html`，无需下载运行时依赖。若使用 OrbitControls 等 addons，应附正确的本地 import map 或相对路径配置。

预览提供固定种子 **17 / 42 / 101**、高度切换、整体/地面港/轨道站视角、分组和锚点辅助线开关、动画开关及全部外观参数控制。镜头可用简单 OrbitControls、预设按钮或自制演示路径，不需要实现正式游戏连续飞镜。重点展示地面装卸、舱体运动、轨道卸载、装配腔净空和离港轴线，并能从背面检查结构。用预览壳的光照展示顺光、逆光和夜景，不要求制作星球自转或地平线系统。

重复桁架、支撑、管线、货箱和停泊设施尽量共享资源并使用 `InstancedMesh`；细缆索提供远景替代表示，避免闪烁与过多微小三角形。不要为每个焊点创建真实灯光。报告高低细节 draw calls、三角形数和动画对象数；远景保留主要轮廓。优先使用 Three.js 标准材质，自定义 shader 遵循 Three.js 色彩输出与对数深度约定，不重复应用曝光或 Gamma。灯光、曝光和最终色调映射放在预览壳。

附固定种子截图、主要设备清单、实际尺寸和净空、分组与锚点说明、资源释放方法。在独立预览里检查创建、移除与释放后没有遗留动画或监听即可；无需运行游戏、访问真实存档或做 30 次游戏导航验收。最终交付可编辑代码与可提取工厂，独立 HTML 演示或截图不能作为唯一结果。
