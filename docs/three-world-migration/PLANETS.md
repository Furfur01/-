# 四类星球接入记录

2026-10-18：已将确认后的 Four Worlds Demo 接到正式入口 `/` 的连续世界。正式代码位于 `scripts/universe/continuous-planets/`，不依赖 Demo 的页面、渲染器或帧循环。原 Demo 继续保留，可独立对照。

## 生成与接口

- 类地星保留大陆、海洋和山系生成；铁星使用确认后的黑曜岩板、熔岩盆地和火山；火星使用赤色台地、分支峡谷和蓝色晶脊；气态星使用原 Demo 的三维云密度、风暴与差速云带。
- `planet-surface.js` 将三类固态星和气态星交给 `continuous-surface.js`。月球继续走原实现，NPC 模型仍由原环境模块处理。
- `makeContinuousConfig()` 以完整坐标和 `four-worlds-2` 生成外观身份。名称、所有者和账号实体 ID 不参与正常星球的外观生成。显式 `seed` 仅用于固定样本。
- 建筑方向和朝向仍由旧的 `legacyPlacementHeight()` 规则选择；随后通过新地形确定基础高度、局部整地与矿坑。基础区域排除晶簇及液面，北极交战区仍为服务端基准球面。
- 气态星设施在 `1.080 R` 的浮空平台上，位于主要云体边界之外；设施附近上层雾密度减弱。北极云顶局部降低，保留原交战坐标。没有加入岩石地表或矿坑。
- 保留 `heightAt`、`cameraHeightAt`、`normalAt`、`buildingTarget`、`pick`、`update`、`dispose`；新增的可见性管理在离开视野时取消工作。设施 ID、模型、尺寸、等级、队列、资源倍率与经营规则均沿用游戏。

## LOD 与资源

固态星改用 Demo 的 cube-sphere 四叉树；父子网格高度渐变、边缘约束和裙边共同处理过渡。几何、材质提示、液面、相机查询共用同一地形函数，并叠加游戏的建筑基础与北极区域规则。

| 画质 | 最大层级 | 叶地块预算 | 缓存地块预算 |
| --- | ---: | ---: | ---: |
| 低 | 12 | 180 | 290 |
| 标准 | 14 | 320 | 510 |
| 高 | 15 | 480 | 760 |

原来的“全球网格 + 4 个精细补片”由连续四叉树取代，统计使用 `cachedBlocks`、`activeBlocks`、`geometryBytes`，不再用补片数量代表内存。星球表面缓存仍为 16 个、设施模型仍为每颗 6 个。最多 4 个可见星球安排精细地形；投影半径不足 40 像素时使用即时低模。离开精细视野释放非根地块，保留小型后备网格。

全世界复用一个地形 Worker，公共等待队列上限 24；每颗表面最多提交两个任务。请求包含版本、完整坐标、地形配置与局部任务身份，隐藏／淘汰后的回复不会提交。Worker 不可用时逐行生成，所有表面共用每帧约 1.6 ms 的主线程预算；单行计算可能略超预算，不同步构建整颗高精度球体。

画质入口为“视角 → 星球画质”，仅存入浏览器本地。画质改变网格误差与装饰／体积步数，不改变地形函数和建筑位置。正式世界继续拥有唯一 renderer、相机和帧循环；新增着色器参加原来的预编译。
